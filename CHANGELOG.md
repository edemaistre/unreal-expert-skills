# Changelog

## v0.2.1 (2026-10-22)

The Scenario for Unreal plugin is public (https://github.com/scenario-labs/unreal-plugin, release 0.2.0), so the skills name it again.

- `unreal-expert` section 4 is again "Generated assets and the Scenario plugin": assets from the plugin are finished by the same skills as assets from the Scenario MCP, and with the plugin installed its `scenario-unreal` skill covers the plugin's local MCP server (price, generate, import, place, save; generation waits for approval in the editor). Descriptions of `unreal-expert` and `unreal-pipeline-automation` and the intro of `unreal-pipeline-automation/references/generated-assets.md` name the plugin again.
- No code or recipe changed. Version stamped everywhere (`metadata.version`, the version line, `__version__`); offline suites pass.

## v0.2 (2026-10-21)

The first release run in Unreal Engine 5.8.3, written after comparing these skills with Epic's Unreal MCP plugin and its in-editor skills (plan: scenario-labs/skills#298).

- **Epic's MCP first.** The lead skill (`unreal-expert`) now covers Epic's toolset protocol (`list_toolsets`, `describe_toolset`, `call_tool`), the 52 toolsets and 830 tools of 5.8.3 (`references/mcp-toolsets.md`, generated by `scripts/gen_toolset_map.py`), `ProgrammaticToolset.execute_tool_script` for batching (four or more calls in a row go through one script), Python Remote Execution on macOS (it needs both sides bound to 0.0.0.0), a project-local Python toolset, and a channel table in `references/channels.md`. New helpers: `ue_mcp.py`, `agent_python_toolset.py`, `gen_toolset_map.py`; `ue_run.py`, `ue_env.py`, `ue_remote.py`, `ue_audit.py` extended.
- **Every specialist skill gained `references/mcp-<domain>.md`** with the argument JSON of each toolset call it needs, multi-call recipes also written as `execute_tool_script` scripts, and traps found while running them (26 more in sections 9 to 11 of `unreal-expert/references/ue-5.8-traps.md`, the rest inside each `mcp-<domain>.md`).
- **New references:** generated assets from Scenario or any generator (`unreal-pipeline-automation/references/generated-assets.md`, `unreal-lighting-rendering/references/generated-skies.md`), Epic's in-editor VFX skills compared (`unreal-vfx/references/engine-skills.md`).
- **Engine facts run on 5.8.3 that change advice:** Python Remote Execution works on macOS when editor and client both bind 0.0.0.0 (Epic's default 127.0.0.1 finds nothing); the default sun is 10 lux; a Control Rig bake run headless holds one pose; Sequencer `add_actors` returns nothing until the sequence is open and a second transform section blends with the first (a camera path covers half the distance); Interchange imports glTF in centimetres with Nanite on, so a "scale by 100" step is a bug; Lumen's cached lighting range is about EV100 -8 to 12 at the default; `-nullrhi` never compiles materials.
- **Run in the engine:** every domain's MCP recipes and in-editor helpers ran on UE 5.8.3 (counts in each SKILL.md status line); offline suites pass on Python 3.9 and 3.14. Each SKILL.md still marks what has not run (for example a Movie Render Graph render end to end, Motion Matching, packaged builds, landscape import).
- **Measured with an arena** (`tests/arena` in the project this repo is built from): the same agent (Sonnet 5.5) with Epic's MCP, no skills against v0.1 against v0.2, on 14 scenarios. Development set (10): score 0.89, 0.94, 0.98; cost per task $0.44, $0.50, $0.33; turns 32, 37, 23; tool errors 6.5, 7.7, 2.2. Held-out set (4): score 0.96, 0.95, 0.95 (a tie at the ceiling); cost $0.66, $0.72, $0.51; turns 56, 50, 38; tool errors 12.0, 7.9, 7.6. One or two trials per cell, one grader, and the v0.2 author saw the development failures: read it as a direction.
- **Fixed after that run (in this release, not covered by the numbers above):** the lighting skill sets a mild sun temperature when the brief asks for warm light and warns that a blank project reads auto-exposure Min/Max Brightness as luminance, not EV100 (a v0.2 run blew a scene out that way); the lighting S1 recipe takes a temperature; the world-building PCG recipe wires the spawner to the graph output. After the fixes d03, h02 and h03 scored 1.00 / 1.00, 1.00 / 1.00 and 1.00 / 0.83 in two trials each.
- Version stamped everywhere: `metadata.version`, the version line, `__version__` in every script.

## v0.1 (2026-09-24)

First release: 10 agent skills for Unreal Engine 5.8, a lead (`unreal-expert`) and nine specialists.

- 10 skills written from 115 expert videos (77 h) and 82 official documentation pages, each with references and an offline-tested `ue_<domain>.py` module; the lead carries the shared toolkit.
- Blind-graded written scenarios (round 1): 51 % without the skills, 95 % with them; all 9 scenarios improved. Measured before the refactor below.
- Includes the refactor after that blind test: every point the graders found missing from both answers, and every error found in a skill's own content, went back into the owning skill. The internal drafts of that day were labelled v0.1 and v0.2 (or v1 and v2); mentions of them in the references and code comments are history, and both are folded into this public v0.1.
- Not yet verified inside Unreal Engine: the engine was not installed when v0.1 was cut (Epic sign-in pending). 1,534 offline checks pass with system Python and fake `unreal` modules only. Treat the in-engine code paths as unverified until a first live run (`tests/OPEN_ISSUES.md` in the build project).
- SKILL.md descriptions quoted so every frontmatter is strict YAML.
- Version stamped everywhere: `metadata.version`, a visible version line, `__version__` in every script.
